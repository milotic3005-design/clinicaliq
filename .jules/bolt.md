## 2024-05-22 - [Prevent OOM with LRU Eviction in Maps]
**Learning:** In long-running Node.js processes like Next.js API routes, unbounded in-memory caches (using `Map`) that store data based on user input (e.g., search or autocomplete queries) will grow indefinitely, leading to an Out-Of-Memory (OOM) leak. JavaScript's `Map` object preserves insertion order, allowing for an efficient LRU implementation where the oldest item is naturally the first one returned by `map.keys().next().value`.
**Action:** When implementing an in-memory cache using a `Map` that handles user-generated inputs, always enforce a maximum size limit. Implement an LRU eviction policy by deleting the `map.keys().next().value` when full, and refresh recency during `set` and `get` operations by explicitly deleting and re-inserting the key, as `Map.prototype.set` does not update insertion order for pre-existing keys.
