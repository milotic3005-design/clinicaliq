## 2025-02-28 - Unbounded In-Memory Cache Leak Fix
**Learning:** This codebase uses an in-memory custom `Map`-based caching solution across multiple Next.js API endpoints. Previously, it only expired items lazily via TTL on `get()`, meaning items that were never requested again would persist forever, causing an unbounded memory leak. This could lead to Out-of-Memory (OOM) errors in production since Node.js processes hold the cache instances.
**Action:** Always implement a `maxSize` eviction policy (e.g. LRU) when storing user-generated queries (like autocomplete queries) in an in-memory `Map`. Since `Map` preserves insertion order, LRU can be easily implemented by doing `this.store.keys().next().value` when size limit is hit, as long as `set()` and `get()` explicitly `delete()` and re-insert the item to refresh its recency.
