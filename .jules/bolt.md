## 2024-05-24 - Autocomplete API Endpoint Caching
**Learning:** The autocomplete endpoint (`/api/v1/suggest`) was firing off multiple external API calls per keystroke and didn't cache identical sequential requests (e.g., typing 'vanc', backspacing, and typing it again). While parallelized with `Promise.allSettled`, this lack of caching leads to sluggish perceived performance, API rate limiting, and redundant processing. When adding caching, using a simple local `Map` directly in the API route file is safer and simpler for non-critical transient UI data than sharing complex, potentially asynchronous caching utilities that might return unexpected shapes.
**Action:** Always verify the shape of cached data objects and prioritize simple module-level `Map` caches for fast, transient, read-heavy UI interactions like autocomplete.
## 2024-05-24 - API Route Memory Leak Prevention
**Learning:** When using local Maps for caching in API routes, unbounded caches can lead to memory leaks and Out-of-Memory (OOM) errors, particularly on endpoints receiving user-generated inputs like autocomplete, because the number of possible input strings is effectively infinite.
**Action:** Always include a max size constraint (`if (cache.size > MAX) cache.clear()`) or use an LRU-like structure to prevent simple Map caches from growing unbounded in production long-running environments.
