## 2024-11-20 - LRU Caching for Autocomplete Performance
**Learning:** In a high-frequency autocomplete API endpoint, caching the fully computed, deduplicated result across multiple external sources is significantly faster than re-running parallel fetches on every keystroke. Furthermore, when implementing an in-memory custom LRU cache using a JS `Map` object, insertion order must be explicitly updated on both `set` and `get` by explicitly deleting and re-setting keys in order to properly implement eviction policies and prevent unbounded memory growth in production Next.js route environments.
**Action:** Use an LRU strategy with bounded sizes (e.g. 500) and explicitly update `Map` recency (delete then re-insert) to ensure optimal cache eviction without memory leaks for endpoints relying on shared data like search autocompletes.
